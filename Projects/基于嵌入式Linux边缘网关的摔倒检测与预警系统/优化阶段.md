### 阶段一：香橙派实机联调与测试


1. **部署流媒体服务器（接收端）**
    
    - 在云服务器（或香橙派本地）部署一个轻量级的流媒体服务器，比如 **MediaMTX** 或 **SRS**，用于接收设备推上来的 RTMP 流，并转换为 WebRTC 或 FLV 供小程序拉流。
        
2. **使用 MQTTX 模拟小程序下发指令**
    
    - 在电脑上下载 [MQTTX](https://www.google.com/url?sa=E&q=https%3A%2F%2Fmqttx.app%2Fzh) 客户端，连接到你的 MQTT Broker（如 broker.emqx.io）。
        
    - 向主题 fall_detection/commands/OrangePi_Gateway_001 发送 JSON 测试指令：
        
        codeJSON
        
        ```
        {
          "cmd": "start_live",
          "rtmp_url": "rtmp://你的服务器IP/live/test"
        }
        ```
        
3. **验证硬件编码与性能**
    
    - 发送指令后，在香橙派终端运行 top 或 htop 命令。
        
    - **核心指标**：观察 CPU 占用率。如果 CPU 占用没有飙升（依然保持在 AI 推理的正常水平），说明 h264_rkmpp 硬件编码调用成功！
        
    - 用 VLC 播放器或网页端拉取视频流，检查画面延迟和清晰度。
        
    - 发送 {"cmd": "stop_live"}，检查推流是否瞬间停止，FFmpeg 进程是否被正确销毁。

### 阶段二：云端后端与微信小程序开发（全链路打通）

设备端准备就绪后，需要补齐“用户端”的拼图。

1. **云端后端（FastAPI / Node.js / SpringBoot）**
    
    - **设备状态管理**：记录设备是否在线、当前是否正在推流。
        
    - **信令中转**：提供 HTTP 接口供小程序调用（如 POST /api/device/start_live），后端收到请求后，再通过 MQTT 下发给香橙派。
        
    - **鉴权与安全**：防止未授权用户恶意拉起摄像头。
        
2. **微信小程序端开发**
    
    - **UI 界面**：设备列表、实时监控画面、历史报警记录（短视频回放）。
        
    - **播放器组件**：根据你选择的协议，使用 <live-player>（需资质）或 WebRTC 组件播放视频流。
        
    - **生命周期管理（极其重要）**：
        
        - 在页面的 onShow 中请求后端下发 start_live。
            
        - 在页面的 onHide 和 onUnload 中**务必**请求后端下发 stop_live，防止用户切后台导致设备一直推流跑流量。

### 阶段三：健壮性与容错优化（企业级打磨）

在跑通主流程后，需要处理各种“异常情况”，防止网关崩溃。

1. **FFmpeg 进程守护**
    
    - 目前我们用 popen 启动了 FFmpeg。如果网络突然断开，FFmpeg 进程可能会卡死或异常退出。
        
    - **规划**：在 LiveStreamer::streamLoop 中，可以通过检查 fwrite 的返回值，如果连续多次写入失败，主动 pclose 并重置状态，等待下一次 start_live。
        
2. **推流心跳保活机制（防幽灵推流）**
    
    - 如果小程序异常崩溃，没发 stop_live 怎么办？
        
    - **规划**：小程序每隔 5 秒发一次 {"cmd": "keep_alive"}，C++ 网关记录最后心跳时间，超过 15 秒没收到心跳，自动掐断推流。
        
3. **网络波动处理**
    
    - 弱网环境下，推流队列 liveQueue_ 可能会满。目前我们设置了队满丢弃旧帧，这很好，但可以增加日志监控丢帧率，如果丢帧率过高，可以动态降低推流帧率（比如从 30fps 降到 15fps）。

### 阶段四：生产部署与版本发布（走向落地）

当 develop 分支在实机上经过长时间（如 7x24 小时）的稳定性测试后：

1. **合并到主分支**
    
    - 将 develop 分支合并到 main 或 master 分支，打上版本标签（如 v1.1.0-LiveStream）。
        
2. **Systemd 守护进程部署**
    
    - 更新 deploy/fall-detection.service 文件，确保网关程序开机自启，且崩溃后能自动拉起。
        
3. **编写使用文档**
    
    - 更新 README.md 和 docs/项目答辩说明文档.md，把新增的“微信小程序按需直播”功能、MQTT 信令格式、流媒体服务器部署要求写进去，这在项目答辩或交付时是极大的加分项。
        

**建议你今天的下一步动作：**  
先不要急着写小程序，**先在香橙派上把程序跑起来，用 MQTTX 模拟发指令，用 VLC 播放器看能不能拉到流。** 只要这一步通了，后面的小程序开发就是纯粹的业务逻辑了。

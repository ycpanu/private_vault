问题总结

1. 编译警告：SPDLOG_ACTIVE_LEVEL redefined

现象
warning: "SPDLOG_ACTIVE_LEVEL" redefined
note: this is the location of the previous definition

原因
include/fall-detection/utils/SysLogger.hpp 中 #define SPDLOG_ACTIVE_LEVEL SPDLOG_LEVEL_TRACE 写在 #include "spdlog/spdlog.h" 之后。spdlog 的 common.h 在包含时会先判断该宏，未定义则默认设为 SPDLOG_LEVEL_INFO，导致后续定义变成重复定义。

修复
把该宏移到文件顶部、所有 spdlog 头文件之前（#pragma once 之后），并删除原来第 18 行的重复定义。

---
2. 运行时错误：Invalid RKNN model version 6

现象
E RKNN: Invalid RKNN model version 6
E RKNN: rknn_init, load model failed!

原因
models/best.rknn 转换时使用的 RKNN Toolkit 版本比板子上 librknnrt.so 运行时新，模型格式版本（6）超出运行时支持范围。

解决方向
- 用与板子运行时匹配的 RKNN Toolkit 版本重新转换模型，或
- 升级板子上的 RKNN 运行时库（librknnrt.so）

---
3. 程序卡在「准备将图像给 NPU 进行极速推理」

现象
程序运行到该日志后无任何输出，一直卡住。

原因
apps/main.cpp 推理循环中，cv::Mat currentFrame 声明后从未从队列取帧（缺少 frameQueue.wait_and_pop(currentFrame) 调用）：

- currentFrame 始终为空 → if (!currentFrame.empty()) 永远为 false
- testFrameCount 永远停在 0 → while(testFrameCount < 50) 变成死循环空转

修复
在循环体内加上阻塞取帧调用 frameQueue.wait_and_pop(currentFrame);，让主线程真正拿到采集线程推入的画面后再推理。

潜在隐患
wait_and_pop 无超时阻塞，若摄像头中途断开（采集线程退出），主线程会永久阻塞。正式版本建议加超时或改用 try_pop + 空帧判断。

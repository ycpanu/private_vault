## volatile
1. **使用场景**
	（1）中断服务程序（ISR）中修改的变量
		主程序循环检测一个标志位，而该标志位由中断服务程序来置位或清除。若不使用 volatile，编译器优化会导致主程序“看不到” ISR 中的修改。
		
	（2）多线程间共享的变量
		一个线程在主线程中循环等待否个条件变量，而另一个工作线程负责在后台设置该变量。由于编译器优化或 CPU 缓存，主线程可能永远无法“看到”工作线程对变量的修改，导致程序死循环。
		
		C++ 中优先使用标准库的 std::atomic 类型，同时保证可见性与原子性操作
		
	（3）映射到硬件寄存器的变量
		在嵌入式系统中，硬件寄存器的地址是固定的，其存储器的值会随着外部设备状态或硬件逻辑自动发生改变，而非由程序指令直接赋值。程序必须实时感知这些硬件层面的变化。
		
		`#define GPIOA_IDR(*((volatile unsigned int*)0x40020010))`

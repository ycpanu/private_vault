## 一、 mutable
### 1. 使用场景
#### （1）用于类成员变量：突破 `const` 函数的限制

通常情况下，如果一个类的成员函数被声明为 `const`，那么这个函数就不能修改类的任何成员变量，因为它保证不会改变对象的状态。

但在实际开发中，我们经常会遇到“逻辑常量性 (Logical Constness)”的需求：即从外部使用者的角度看，对象的状态没有改变，但在对象内部，为了实现某些功能（如缓存、计数器、线程锁），我们需要修改某些特定的变量。

把这些特定的变量声明为 `mutable`，就可以在 `const` 函数中修改它们。

##### 典型的应用场景

- **缓存 (Caching)：** 第一次读取时计算结果并保存，后续直接返回。
    
- **访问计数 (Counting)：** 统计某个 `const` 接口被调用的次数。
    
- **线程锁 (Mutex)：** 在 `const` 函数中加锁以保证线程安全。
    

#####  代码示例：访问计数器

C++

```
#include <iostream>

class DataObject {
private:
    std::string data;
    mutable int readCount; // 声明为 mutable

public:
    DataObject(std::string d) : data(d), readCount(0) {}

    // 这是一个 const 函数，保证不修改对象的核心数据
    std::string getData() const {
        readCount++; // 即使在 const 函数中，也可以合法修改 mutable 变量
        return data;
    }

    int getReadCount() const {
        return readCount;
    }
};

int main() {
    const DataObject obj("Hello C++");
    
    std::cout << obj.getData() << std::endl; // 输出: Hello C++
    std::cout << "读取次数: " << obj.getReadCount() << std::endl; // 输出: 读取次数: 1
    
    return 0;
}
```

### （2） 用于 Lambda 表达式：取消按值捕获的只读限制

在 C++11 引入的 Lambda 表达式中，如果你**按值**捕获了外部变量（例如 `[x]` 或 `[=]`），闭包（Lambda 函数体）默认会将这个变量的副本视为 `const` 的，你无法在 Lambda 内部修改它。

在 Lambda 参数列表后加上 `mutable` 关键字，就可以取消这个限制，允许你修改捕获进来的变量**副本**（注意：依然不会改变外部原来的变量）。

#### 代码示例：Lambda 按值捕获

C++

```
#include <iostream>

int main() {
    int x = 10;

    // 错误写法：x 被按值捕获，默认是只读的
    // auto f1 = [x]() { x++; }; // 编译报错

    // 正确写法：使用 mutable
    auto f2 = [x]() mutable {
        x++; // 允许修改 x 的副本
        std::cout << "Lambda 内部 x = " << x << std::endl;
    };

    f2(); // 输出: Lambda 内部 x = 11

    // 外部的 x 并没有被改变，因为 Lambda 内部修改的是副本
    std::cout << "Lambda 外部 x = " << x << std::endl; // 输出: Lambda 外部 x = 10

    return 0;
}
```

> **核心原则：** 不要滥用 `mutable`。它应该仅仅用来修饰那些**不影响对象可观察状态**（即外部看起来不影响业务逻辑）的隐藏状态变量。如果一个变量代表了对象的核心属性，绝不应该用 `mutable` 来绕过 `const` 设计。

### 2. mutable 在多线程锁 (std::mutex) 中的应用
在 C++ 多线程编程中，`mutable` 与 `std::mutex` 的结合是为了解决一个经典的矛盾：**如何在一个 `const`（只读）成员函数中保证线程安全。**

准确地说，这对组合主要解决的是**数据竞争 (Data Race)** 问题。至于死锁 (Deadlock)，它更多与锁的获取顺序有关，但 `mutable` 是构建底层线程安全类的基石。

以下是它们配合使用的底层逻辑和具体实现。

#### 核心矛盾：`const` 方法与线程安全的冲突

在设计良好的 C++ 类中，不修改对象核心状态的“读取”函数（如 `get()` 方法）都应该被声明为 `const`。但在多线程环境下，即使是单纯的读取操作，也必须加锁。因为如果线程 A 正在读取数据，而线程 B 正在写入数据，就会发生数据竞争，导致读取到半截数据或程序崩溃。

矛盾由此产生：

1. 为了防止数据竞争，读取函数（`const` 方法）内部必须对 `std::mutex` 加锁。
    
2. 调用 `mutex.lock()`（或使用 `std::lock_guard`）会**物理上改变 mutex 对象的状态**（从无锁变为有锁）。
    
3. 但是，C++ 编译器严格禁止在 `const` 成员函数中修改类的任何成员变量。
    

**如果不使用 `mutable`，你将被迫面临两个糟糕的选择：**

- 放弃把读取函数设为 `const`，这破坏了类的接口语义，也导致无法向 `const` 引用传递该对象。
    
- 不在读取函数中加锁，直接导致数据竞争，程序在多线程下崩溃。
    

#### 完美解法：`mutable std::mutex`

将类中的 `std::mutex` 声明为 `mutable`，明确告诉编译器：**这个锁并不属于对象的“逻辑业务状态”，修改它不代表对象本身的数据被篡改了。** 这样就可以合法地在 `const` 方法中进行加锁操作。

##### 经典代码范例：线程安全的银行账户

C++

```
#include <iostream>
#include <mutex>
#include <thread>
#include <vector>

class BankAccount {
private:
    double balance;
    // 关键点：声明为 mutable，允许在 const 函数中加锁
    mutable std::mutex mtx; 

public:
    BankAccount(double initial_balance) : balance(initial_balance) {}

    // 写入操作（非 const）：修改核心数据 balance
    void deposit(double amount) {
        std::lock_guard<std::mutex> lock(mtx);
        balance += amount;
        // lock_guard 离开作用域时自动解锁
    }

    // 读取操作（const）：不修改核心数据，但必须加锁以防数据竞争
    double getBalance() const {
        // 如果 mtx 不是 mutable，这里会编译报错！
        std::lock_guard<std::mutex> lock(mtx);
        return balance;
    }
};

void simulate_transactions(BankAccount& account) {
    for (int i = 0; i < 1000; ++i) {
        account.deposit(10.0);
    }
}

int main() {
    BankAccount myAccount(0.0);

    // 创建多个线程并发存款
    std::thread t1(simulate_transactions, std::ref(myAccount));
    std::thread t2(simulate_transactions, std::ref(myAccount));

    // 创建一个线程并发读取
    std::thread t3([&myAccount]() {
        for (int i = 0; i < 5; ++i) {
            // 安全读取，不会与存款线程发生数据竞争
            std::cout << "Current Balance: " << myAccount.getBalance() << std::endl;
            std::this_thread::sleep_for(std::chrono::milliseconds(2));
        }
    });

    t1.join();
    t2.join();
    t3.join();

    std::cout << "Final Balance: " << myAccount.getBalance() << std::endl;
    return 0;
}
```

#### 机制解析与纠偏

1. **解决数据竞争 (Data Race)：** 在上面的 `getBalance() const` 中，`std::lock_guard` 成功获取了锁。这意味着如果此时 `deposit()` 正在执行，`getBalance()` 会阻塞等待，直到写入完成。反之亦然。这就彻底杜绝了“读-写”竞争。
    
2. **维持逻辑常量性 (Logical Constness)：** 外部调用者看到 `getBalance() const` 的签名，就能安心地确认“调用这个方法绝对不会改变我的银行余额”。`mutable` 将并发控制的实现细节完美地封装在了类内部。
    
3. **关于死锁 (Deadlock)：** 需要澄清的是，`mutable std::mutex` 仅仅赋予了你在 `const` 函数中加锁的权限。**它本身并不能自动防止死锁。** 如果在复杂的类结构中，你嵌套调用了多个保护不同 `mutable mutex` 的 `const` 方法，且加锁顺序不一致，依然会导致死锁。防止死锁通常需要依靠 `std::scoped_lock`（C++17）来同时获取多个锁，或严格规定加锁层级。

## 二、explicit

**`explicit`** 是 C++ 中的一个核心防错关键字，字面意思是“显式的”。它的唯一使命就是：**阻止编译器在背后偷偷摸摸地进行“隐式类型转换”。**

在 C++ 中，如果类的构造函数只有一个参数（或者其他参数都有默认值），编译器会自动利用这个构造函数，将该参数的类型隐式转换为类的类型。这虽然有时候很方便，但往往会导致极为隐蔽的逻辑 Bug。

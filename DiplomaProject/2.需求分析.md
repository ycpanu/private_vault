
本章主要对基于微信小程序的考研择校辅助系统进行需求分析。首先从经济、技术和市场三个维度进行系统的可行性分析，论证项目开发的前提条件；其次，通过用例图和用例规约详细阐述系统的功能需求；接着，结合活动图对系统的核心业务流程进行梳理与分析；最后，明确系统在性能、安全性等方面的非功能性需求。

## 2.1 可行性分析

在软件工程的生命周期中，可行性分析是系统开发前必不可少的阶段，旨在以最小的代价在最短的时间内确定问题是否能够解决。本节将结合考研择校小程序的实际情况，对其进行详细论证。

### 2.1.1 经济可行性

本系统主要作为本科毕业设计及面向考研学生的公益性/低收费辅助工具。在开发阶段，前端采用免费的微信开发者工具，后端采用开源免费的 Java 语言、Spring Boot 框架以及 MySQL 数据库，无需支付昂贵的软件授权费用。在系统部署与运行阶段，可租用腾讯云或阿里云的低配轻量应用服务器，结合开源的考研考情数据集，整体硬件与数据成本极低。因此，本系统在经济上是完全可行的。

### 2.1.2 技术可行性

本系统采用成熟的前后端分离架构。前端移动端采用微信小程序原生技术及 Vant Weapp 组件库开发，能够快速构建跨平台、高响应的移动端界面；后台接口端采用 Java 语言配合 Spring Boot 与 MyBatis 框架，该技术栈在企业级开发中具有极高的成熟度与稳定性；数据库管理系统使用 MySQL 8.0 数据库。系统前后台交互采用了 AJAX（Asynchronous JavaScript and XML，异步的JavaScript与XML）技术与 JSON 数据格式。此外，集成外部大语言模型 API 实现智能问答的技术路线也十分成熟。因此，本系统在技术上是完全可行的。

### 2.1.3 市场可行性

近年来，全国硕士研究生报考人数维持高位，尤其是计算机等热门理工类学科的竞争日益激烈。当前考研信息存在高度碎片化的问题，考生获取历年复试线、专业课大纲等核心考情数据的门槛较高。目前市场上虽有一些考研辅导 App，但往往伴随高昂的课程推销，缺乏一款轻量级、专注于“考情查询与智能择校”的移动端工具。本系统依托微信庞大的用户基数，即开即用，完美契合了考研学子利用碎片化时间查询信息的需求。因此，本系统在市场上具有广阔的应用前景和极高的市场可行性。

## 2.3 业务流程分析

为了更清晰地展示系统的内部流转机制，本节对系统中的核心业务流程进行详细描述与分析。

（1）用户查询院校考情数据的业务流程如下。

流程描述：用户登录小程序后，进入“院校库”模块；在搜索框中输入院校名称或通过下拉菜单选择目标省份与学科门类（如 0854 电子信息）；系统前端发起数据请求，后端接收请求并查询 MySQL 数据库中的院校信息表与分数线表；如果数据库中存在相关数据，后端将数据封装为 JSON 格式返回，前端解析并展示该院校的历年复试线、招生人数及专业课科目详情；如果数据库中无相关数据，前端提示“暂无该院校最新考情数据”。

## 2.4 非功能性需求分析

除了满足考研学生与管理员的基础功能操作外，为了保证系统的稳定性与用户体验，本系统还需满足以下非功能性需求。

（1）性能需求：系统应具备良好的响应速度。由于移动端网络环境多变，小程序端的“院校列表查询”与“单校考情详情展示”接口的平均响应时间应控制在 2 秒以内；系统需要能够承受考研报名期间（每年 9 月至 10 月）的高并发访问，保证系统运行不崩溃。

（2）安全性需求：系统需要保障用户隐私与数据安全。用户密码等敏感信息必须经过不可逆加密（如 BCrypt）后存储入库；后台管理端需设置严格的权限校验机制，防止越权操作；系统后端 API 需具备防范 SQL 注入及 XSS 跨站脚本攻击的能力。

（3）兼容性需求：小程序端必须保证在主流的 Android 与 iOS 移动设备上均能正常展示，UI 布局不能出现严重的错位或文字重叠；Web 管理端需兼容 Google Chrome、Microsoft Edge 等主流浏览器。

# 实验3：使用Selenium进行自动化功能测试 **一、 测试环境** * **操作系统**：Windows * **开发与测试工具**：IntelliJ IDEA, Maven * **测试框架**：JUnit 5, Selenium WebDriver (Java API) * **浏览器及驱动**：Google Chrome 及对应版本的 ChromeDriver **二、 被测系统简介** 本次测试对象选择了专门用于自动化测试练习的 Web 应用 Sauce Demo (https://www.saucedemo.com/)。该系统是一个典型的电商网站示例，包含了标准的用户登录、商品列表浏览、购物车管理以及结账全流程，适合用于验证 UI 自动化脚本的各项功能。 **三、 测试目标** 1. 验证系统登录页面的核心逻辑（包含合法用户登录、密码错误拦截、黑名单用户锁定提示）。 2. 验证商品列表页面的核心交互功能（商品添加至购物车、购物车动态角标数字更新）。 3. 通过页面工厂模式（POM）实现测试脚本与页面元素的分离，提升自动化测试代码的可维护性[cite: 1]。 **四、 测试功能点与测试用例** 针对登录页和商品页，共设计并实现了以下 5 个自动化测试用例[cite: 1]： | 用例编号 | 所属页面 | 测试功能点 | 输入/前置操作 | 预期结果 | 定位方式示例 | | :--- | :--- | :--- | :--- | :--- | :--- | | **TC_01** | 登录页 | 正确登录跳转 | 输入账号 `standard_user`，密码 `secret_sauce`，点击登录 | 成功跳转至商品列表页，页面左上角显示 "Products" 标题 | `id`, `name` | | **TC_02** | 登录页 | 密码错误拦截 | 输入账号 `standard_user`，密码 `wrong_pass`，点击登录 | 登录被拦截，页面显示提示 "Username and password do not match" | `cssSelector` | | **TC_03** | 登录页 | 锁定用户拦截 | 输入账号 `locked_out_user`，密码 `secret_sauce`，点击登录 | 登录被拦截，页面显示提示 "Sorry, this user has been locked out" | `cssSelector` | | **TC_04** | 商品页 | 动态添加购物车 | 正确登录后，点击第一个商品背包的 "Add to cart" 按钮 | 按钮文本由 "Add to cart" 动态更新为 "Remove" | `xpath` | | **TC_05** | 商品页 | 购物车角标更新 | 正确登录后，点击第一个商品背包的 "Add to cart" 按钮 | 页面右上角购物车图标出现红色角标，并显示数字 "1" | `cssSelector` | **五、 测试代码** *(请将下方的 Java 代码复制粘贴到这里作为附录)*[cite: 1]

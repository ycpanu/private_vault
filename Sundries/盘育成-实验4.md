# 实验4：使用JMeter进行性能测试

## 一、 测试环境

- **操作系统**：Windows 11
    
- **测试工具**：Apache JMeter 5.6
    
- **Java环境**：JDK 11
    
- **网络环境**：局域网/宽带连接
    

## 二、 被测系统及测试方案

### 2.1 被测系统简介

本次性能测试的被测对象为 Altoro Mutual 银行演示系统（`http://demo.testfire.net/`）。该系统包含了典型的 Web 银行业务流程，适合进行高并发下的负载性能评估。

### 2.2 测试方案制定

本次测试旨在模拟多用户并发访问系统的核心业务链路，考察系统在持续负载下的响应能力和稳定性。

- **业务链路（测试请求）**：
    
    1. 访问首页 (`GET /index.jsp`)
        
    2. 用户登录 (`POST /bank/login.aspx`) —— **包含参数化**
        
    3. 查看账户信息 (`GET /bank/main.jsp`)
        
    4. 退出系统 (`GET /bank/logout.aspx`)
        
- **测试数据参数化**：使用 CSV Data Set Config 驱动，准备了多个有效测试用户（如 admin/admin, jsmith/demo1234 等），并在登录请求中使用 `${username}` 和 `${password}` 进行参数化调用，真实模拟不同用户的登录行为。
    
- **负载模式（并发策略）**：
    
    - **并发线程数**：50 个虚拟用户。
        
    - **Ramp-Up 时间**：10 秒（每秒启动 5 个用户）。
        
    - **持续时间**：900 秒（15 分钟）。
        

## 三、 测试过程与脚本开发

1. **基础配置**：在 JMeter 测试计划中添加 HTTP Request Defaults 统一配置服务器域名，并添加 HTTP Cookie Manager 用于自动维持用户的登录会话状态（Session）。
    
2. **脚本开发**：按照设计好的业务链路，依次添加 4 个 HTTP Request 取样器。
    
3. **参数化配置**：通过 CSV Data Set Config 组件读取本地的 `users.csv` 文件，实现每次循环时动态提取不同的账号密码进行登录。
    
4. **调试验证**：通过“察看结果树”监听器进行单线程的试运行，确认各个请求的 Request Header 和 Response Data 均符合预期，登录及重定向动作执行成功。
    
5. **正式压测**：调整线程组配置至 50 并发用户并设置调度器运行 15 分钟，启动测试并收集数据。
